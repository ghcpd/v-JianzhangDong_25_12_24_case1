Final Prompt: Update README and Add Test/CI Helpers

You are responsible for reviewing outdated project documentation and fixing CI/test tooling so that the project can be reliably deployed and tested locally.

Goals & Constraints
- Only modify `README.md`. You may add new files, but do not change any other existing project files.
- Create a backup of the original README named `README_backup.md` before applying any edits.
- Ensure changes are reproducible on Windows and POSIX systems.

Required Tasks (must be automated and repeatable)
1) README
  - Update `README.md` so users can successfully deploy the project and run tests.
  - Fix incorrect or missing instructions (entry point, env vars, virtualenv activation, expected output, testing instructions).
  - Make instructions cross-platform (PowerShell/Bash) and explicit about using `.venv`.

2) Virtual Environment
  - Create a clean `.venv/` environment; if `.venv/` exists, delete and recreate it.
  - Install packages from `requirements.txt` into `.venv`.
  - Upgrade `pip` in the environment and install `pytest` if not in requirements.
  - Update `.gitignore` to exclude `.venv/`, `logs/`, and common Python artifacts.

3) test runner helper: `auto_test.py`
  - Start the project (verify `python app.py` runs successfully).
  - Use the interpreter inside `.venv/` to execute all test scripts inside `tests/` (do not rely on pytest discovery specifics; explicitly run all `*.py` in `tests/`).
  - Ensure a `logs/` directory exists and write all test output to `logs/test_run.log`.
  - Exit with non-zero code if tests fail.

4) Report: `report.json`
  - Create `report.json` documenting each CI/documentation fix with entries following this schema:
    {
      "problems": [
        {
          "id": <integer>,
          "file": "README.md",
          "line_numbers": [<list of ints>],
          "original": "<string>",
          "updated": "<string>",
          "fix_explanation": "<string>"
        }
      ]
    }
  - Include an entry for every substantive README change.

Validation & Deliverables
- Run `auto_test.py` and ensure tests run and `logs/test_run.log` is created with the test results.
- All tests should pass on a fresh `.venv` (or the runner should clearly fail and return non-zero if not).
- Commit and document created files: `README_backup.md`, updated `README.md`, `.gitignore`, `auto_test.py`, `report.json`, and `logs/test_run.log` (logs may be generated by running `auto_test.py`).

Acceptance Criteria
- `README_backup.md` exists and is an exact copy of original README.
- `README.md` contains correct, clear, cross-platform run and test instructions.
- `.venv` is created from scratch and contains required dependencies.
- `auto_test.py` starts the project, runs tests using `.venv`, and writes `logs/test_run.log`.
- `report.json` documents the README changes with proper line numbers and explanations.
- No other existing repository files are modified.

Notes
- Prefer explicitly running test files rather than relying solely on pytest discovery (tests may be named `case_*.py`).
- Keep messages concise and machine-actionable so this prompt can be used by an automated agent.

Do not change any other files.
